# Бриф на сайт

Пошаговая анкета для клиентов. Статика: HTML, CSS и JS без сборщика, лежит на GitHub Pages.
Открывается по адресу `ваш-сайт/brief/`. На главной странице на неё ведёт кнопка «Заполнить бриф».

## Файлы

| Файл | Зачем |
|---|---|
| `index.html` | разметка вступления, финала, нижней навигации и подвала |
| `styles.css` | оформление (те же цвета, шрифты и кнопки, что на основном сайте) |
| `app.js` | вся логика. **Вопросы лежат массивом `STAGES` в начале файла** |
| `config.js` | только адрес приёмника (`endpoint`) |
| `worker.js` | код для Cloudflare Worker, на сайте не нужен |

## Как работает

- Вопросы выдаются этапами по 3–5 штук. Кнопка «Далее» проверяет обязательные вопросы: пустые подсвечиваются, страница прокручивается к первому.
- Ответы автоматически сохраняются в браузере (`localStorage`). Закрыли вкладку, вернулись, и они на месте, с подсказкой «Черновик восстановлен». После успешной отправки черновик стирается. **Приложенные файлы в черновик не попадают**, их придётся приложить заново.
- Внизу точки-этапы: по ним можно прыгать. Обязательные вопросы проверяются при отправке на всех этапах.
- **Пока `config.js` пустой**, вместо отправки скачивается файл `brief-имя-дата.txt` с ответами, а на финальном экране просят прислать его в Telegram.
- **Если отправка не удалась** (нет связи, ошибка приёмника), копия ответов тоже скачивается автоматически. Ответы не теряются.

## Как менять вопросы

Откройте `app.js`, найдите массив `STAGES`. У каждого вопроса поля:

```js
{ id: 'q1', key: 'why', type: 'textarea', required: true, important: true, summary: true,
  label: 'Зачем бизнесу сайт именно сейчас?',
  hint:  'Подсказка человеческим языком под вопросом.' }
```

- `id` и `key` должны быть уникальными. `key` попадает в черновик.
- `type`: `textarea` (большое поле), `text` (одна строка), `links` (ссылки по одной на строку), `files` (загрузка), `consent` (галочка согласия).
- `required: true` делает вопрос обязательным, `important: true` ставит плашку «Важно».
- `summary: true` добавляет ответ в первое сообщение-сводку в Telegram.
- Этап добавляется новым объектом в массив. Счётчики и точки подстроятся сами.
- Worker менять не нужно: вопросы и ответы приходят к нему готовыми.

## Как подключить отправку в Telegram

Ответы идут через Cloudflare Worker, чтобы токен бота не лежал на сайте.

1. **Бот.** В Telegram откройте `@BotFather`, команда `/newbot`, получите **токен**.
2. **Чат.** Напишите своему боту любое сообщение. Затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}`. Это ваш **CHAT_ID**.
3. **Worker.** На [dash.cloudflare.com](https://dash.cloudflare.com) откройте Workers & Pages → Create → Worker.
   Вставьте код из `worker.js` и нажмите Deploy.
4. **Переменные.** В Worker откройте Settings → Variables and Secrets и добавьте:
   - `BOT_TOKEN` (тип Secret): токен бота;
   - `CHAT_ID`: id из шага 2;
   - `ALLOWED_ORIGIN`: адрес сайта, например `https://ваш-логин.github.io` (без `/` в конце).
5. **Адрес.** Скопируйте адрес Worker (`https://имя.ваш-логин.workers.dev`) и вставьте в `config.js`:
   ```js
   window.BRIEF_CONFIG = { endpoint: 'https://имя.ваш-логин.workers.dev' };
   ```
6. Заполните бриф сами для проверки: в Telegram придёт сводка, затем по сообщению на каждый этап, затем файлы.

### Что приходит в Telegram

1. Сводка: имя, компания, контакт и главные ответы (вопросы с `summary: true`).
2. Каждый этап отдельным сообщением, вопросы жирным.
3. Пустые вопросы и пустые этапы не показываются.
4. Длинные ответы режутся по абзацам под лимит Telegram 4096 символов, фраза посреди не рвётся.
5. Приложенные файлы приходят документами.

## Ограничения

- Файлов до 10, каждый до 18 МБ (меняется в `SETTINGS` в начале `app.js`).
- Cloudflare принимает запрос до 100 МБ на бесплатном тарифе. Десять файлов по 18 МБ могут не поместиться, тогда придёт ошибка, и сработает скачивание копии ответов.
- Telegram принимает файлы до 50 МБ.

## Что ещё подставить

- Ссылки на документы в подвале и в галочке согласия сейчас заглушки (`href="#"`, атрибут `data-doc`). Когда будут страницы, замените адреса.
- Фото на финальном экране: `index.html`, блок `.done__photo`. Сейчас то же, что на главной.
- Срок ответа «в течение 1–2 рабочих дней» написан в `index.html`, блок `.done__steps`.
- Текст «15–20 минут» на вступлении: `index.html`, блок `.intro__lead`.
